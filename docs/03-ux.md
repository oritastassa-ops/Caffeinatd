# Caffeinatd — UX Design (Phase 3)

## Design language

Raycast's command bar + Linear's density + Notion's calm. Concretely:

- **Type**: Inter (UI) at 13–15px body, tight tracking on headings; tabular numerals for macros/weights.
- **Color**: near-black `#0A0A0B` dark surface / warm off-white light surface; one accent
  (amber/caffeine `#D97706`) used *only* for primary actions and the active nav item. Semantic
  greens/reds reserved for done/over-budget states. All colors are CSS variables; dark + light
  ship day one (class-based, respects system preference).
- **Spacing**: 4px grid; cards are `radius-xl`, 1px hairline borders, no drop-shadow soup.
- **Motion**: 150–200ms ease-out on overlay/hover/list transitions. Nothing bounces.

## Information architecture

```
⌘K Command bar (global overlay — the assistant lives here)
├─ Today        — the home screen: daily plan, agenda, priorities, macros ring, sleep rec
├─ Tasks        — priority-grouped list, quick complete, categories/projects
├─ Calendar     — week list view (read model of Google Calendar)
├─ Fitness      — recent workouts, weekly volume, PR/overload hints
├─ Nutrition    — today's log, daily totals vs goals, 7-day trend
├─ Memory       — what the assistant knows about you; edit/delete any fact
└─ Settings     — provider status, Google connect, goals, timezone, export
```

Memory as a *visible, editable screen* is a deliberate trust feature: no black-box profile.

## Keyboard-first

- `⌘K` / `Ctrl+K` anywhere → command bar. Plain typing = natural language to the assistant.
- `Enter` submits; `Esc` dismisses; response renders inline in the overlay with **action chips**
  (e.g. `✓ Task created · Undo`) so she sees exactly what the system did.
- `g` then `t/c/f/n` power-user nav (later milestone); all interactive elements focus-visible.

## Core flows

**1. Capture (the 80% flow)** — `⌘K` → "remind me to call mom tomorrow" → chip `✓ Task created:
Call mom — tomorrow` → `Esc`. Total ≤ 3 seconds, never leaves the current screen.

**2. Morning** — opens app → Today already shows: greeting + plan overview sentence, top 3
priorities, timeline of events with free windows marked, workout + meal suggestion, bedtime rec.
Zero interaction required — this is the "speaks first" moment.

**3. Ambiguity** — "schedule dentist Thursday at 3" with a conflict → assistant replies in the
overlay with the conflict and 2 proposed slots as tappable chips; tapping one books it.

**4. Logging** — "I ate chicken and rice" → chip shows estimated macros inline (`~520 kcal · 42P
· 55C · 12F · Undo`) so estimation errors are visible and reversible at capture time.

## Empty & degraded states

Every view has a designed empty state with the command to fill it ("Press ⌘K and tell me about
your workout"). Calendar not connected → inline connect card, not an error. AI provider down →
banner on the command bar; manual CRUD in each view still works (the app is usable without AI).

## Mobile

Same web app, responsive: sidebar collapses to a bottom tab bar; a floating ✦ button replaces ⌘K.
PWA installable so it sits on her home screen like a native app. (Voice input is the roadmap's
first extension — the browser SpeechRecognition API slots into the same command bar.)
